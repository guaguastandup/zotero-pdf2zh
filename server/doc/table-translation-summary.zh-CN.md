# 当前表格翻译与排版总结

实现与验证记录日期：2026-10-22；文档说明更新日期：2026-10-29。
本文说明实现与已知边界。历史验证结果不代表本次提交已重新运行测试。
英文规则说明见 [table-modes.md](table-modes.md)，PR 文案和提交范围见
[table-translation-pr.md](table-translation-pr.md)。

## 1. 用户入口与兼容性

- 原“翻译表格文字”仍是总开关且默认关闭；新增“更美观的表格”默认开启，总开关关闭时不可操作，只有两者均启用才发送 `tableMode="fixed"`，因此默认不会启用表格处理。
- 总开关关闭时，新选项禁用；新选项关闭时继续使用原生表格翻译。
- 旧下拉框值、字符串 `"true"`、缺失字段不会隐式启用新流程。
- 上传前通过 `/health.tableModes` 确认 Server 支持所选模式，防止旧 Server 静默忽略设置。
- API 支持 `preserve`、`fixed`；`adaptive` 尚未实现、不出现在界面中，Server 明确拒绝。
- 仅支持 pdf2zh-next Python 引擎；适配器锁定 BabelDOC 0.6.2，在 pdf2zh-next 2.9.0 上验证。独立 exe、其他引擎及 OCR workaround 不支持。

## 2. 从原文到译文的处理链

1. 提取原生表格区域中的文字，保留原字形、字体和坐标快照。
2. 根据基线、持续列间隙、重复数值行及实际横竖线，恢复保守的本地候选单元。
3. 将整表原始片段、ID、原文、相对坐标和候选关系交给当前文本 LLM 做结构分析。
4. 本地校验模型建议：片段 ID、唯一归属、阅读顺序、数值、跨线、跨列、夹入内容和障碍物均需满足规则。
5. 经过校验的语义单元才进入普通翻译。正文和不同表格分别构造原生批次，继续使用引擎原来的批量上限、占位符校验与回退机制。
6. 译文在受限范围内排版、验证实际输出；不满足条件时恢复对应原字形。

结构分析不返回译文或输出坐标；文献中的文字只作为待处理内容，不执行其指令。
默认上限为 1,200 个原始片段、80,000 字符的分析提示词。超限、分析失败或响应非法时保留原表，不截断输入，也不把剩余文字拆成零散词语继续翻译。
没有 LLM 接口时仍可使用保守的本地恢复路径。代码/伪代码判定复用同一次结构分析；代码内容、注释、缩进、符号保持原样，只允许明确独立的标题翻译。

## 3. 什么需要翻译，什么保持原样

| 内容 | 当前规则 |
| --- | --- |
| 完整句子、描述 | 作为完整单元翻译；不因句中出现专名而拆散。 |
| 普通标题、指标名称、描述性技术术语 | 应翻译；“属于专业术语”本身不是保留理由。 |
| 真正的方法/产品/数据集名称、标识符 | 可原样保留；仍依赖模型判断和结构校验。 |
| 缩写 | 上下文能明确含义才翻译，否则保留；不能仅凭末尾句点判断。 |
| 独立数值、符号、纯标识符 | 沿用源字形与位置，不消耗进相邻文字单元。 |
| 技术名称列表 | 结构识别后跳过翻译和重新排版，保留原字体、起点及换行。 |
| 译文实质未变 | 忽略空白、标点后的内容一致时，直接沿用源字形。 |
| 代码/伪代码 | 原样保留；不把注释单独拿去翻译。 |
| 图片、旋转文字 | 保留并作为障碍物；不上传图片内容做表格分析。 |

独立标签可分成“保留部分”和“翻译部分”，但各部分必须精确覆盖原文、完整映射到原字形，不能切开连字。保留部分不参与字体映射或重新排版；翻译部分不能推动保留名称或挤入相邻行。

对于“描述名称＋括号代码/范围”，本地放行还要求同列至少三个不同代码及对应数值行。符合这一指标列证据时，翻译描述、保留代码，而不是因为有 `(M1)` 就冻结整句。单独一个带版本号的产品名不足以触发该覆盖。

中文输出还保留有限的完整名称保护，避免将已恢复的名称译成一半中文、一半原文。这不是完整的命名实体识别器，也不能保证全篇术语统一。

## 4. 单元格与跨列判定

- 根据真实文字基线聚行、排序，避免字框高度不同导致词序或行归属错误。
- 已有同列几何证据的候选，不再只因为词间距超过字号 1.5 倍就拒绝。
- 实际横竖线、其他单元格、图片和数值保护继续有效；推断边界并不等同于真实单元格线。
- 跨列完整标题：必须有完整句子分类、独占源行，且没有实际竖线分隔，才能作为跨列单元翻译。斜体不是放行条件。
- 粘连表头：至少三条重复数值行提供列中心，还需相邻短表头层及一致的词块归属，才尝试按列拆开。不能切字形、不能占用相邻列中心；证据不足仍保留源片段。
- 拆分后，根据上下层原文的共同中心恢复对齐和文字范围，避免短上标题与长下标题分别沿不同左边缘排版。
- 没有完整恢复行列网格、合并单元格或自动改变表格行高列宽。

## 5. 对齐、换行、字号与公式

| 项目 | 规则 |
| --- | --- |
| 水平对齐 | 优先继承源表左/中/右对齐；不确定时沿用源左边缘。换行不自动强制居中。 |
| 纵向对齐 | 同行使用共同顶部；源字号相同的多行同级表头协调预检字号。 |
| 多行均衡 | 在支持的 Unicode 单元中，保持行数，尽量均衡非空白字符数量，前行优先较长；不拆拉丁单词，遵守标点限制。 |
| 不支持的均衡情况 | 公式等复杂片段保留原生换行，再按源对齐，不承诺每行字数相等。 |
| 缩放 | 100% 到 70%，每次下降 5%；不启用无协调的段落空间扩张。 |
| 排版归位 | 实际输出整体尺寸能容纳时，先整体平移回原分配框；不在这一步改变字号、内部间距或行数。 |
| 公式计量 | 同时考虑逻辑字符框、字形视觉框和实际占用；可见公式参与居中；重复对齐不重复添加公式偏移。 |

这使“数字＋百分号”不会因视觉框比逻辑占用窄而重叠，也使含数学符号的标题不会漏算行末符号宽度。

## 6. 拒绝与回退的具体条件

| 检查 | 当前边界 |
| --- | --- |
| 原生排版 | 原生排版不能完成该单元时，尝试下一字号。 |
| 标签锚点 | 单行局部替换不能跨行或侵犯保留部分。 |
| 单元及实际字形边界 | 容差 0.05 磅。 |
| 拉丁标识符 | 已恢复的完整词不能从内部换行切开。 |
| 文字障碍 | 允许最多 `min(0.3 磅, 源字号的 4%)` 浅交叠。 |
| 图片、旋转文字 | 严格避让，不随文字浅交叠规则放宽。 |
| 相邻单元格 | 对整个分配范围和源文字范围检查，并分配共享空白。 |
| 最小字号 | 70% 仍不满足时，恢复原文。 |

日志记录源片段、各次字号比例及失败原因，区分原生放置、标签锚点、单元边界、词被拆开、图片/文字障碍、实际字形越界和排版单元为空。

## 7. 运行隔离与实现位置

- 插件偏好、类型、双语文案、能力校验：`plugin/src/modules/pdf2zhTableMode.ts` 及对应界面接线。
- Server 请求与命令接线：`server.py`、`utils/config.py`、`utils/execute.py`、`table_mode.py`。
- 进程与适配器：`table_runner.py`、`table_process.py`、`table_runtime.py`。
- 结构、策略、批量：`table_structure.py`、`table_columns.py`、`table_semantics.py`、`table_batching.py`。
- 字形归属与保护：`table_labels.py`、`table_code.py`、`table_images.py`。
- 排版与几何恢复：`table_layout.py`、`table_geometry.py`。
- `table_characters.py` 是内部逐字范围实验，不是界面或默认路径；默认限制另见英文说明。

适配器只在显式启用的翻译进程中安装，并在结束时恢复。spawn 子进程单独安装，fork 子进程先恢复继承钩子，debug/同进程路径也有覆盖。没有修改已安装引擎文件。

## 10. PR 准备边界

建议提交：插件接线、Server 入口、表格模块、对应测试（包括 Windows 环境隔离 mock 修正）、两份源码 fixture 及功能说明。`table-translation-pr.md` 是 PR 正文草稿与本地准备笔记，可留在本地，无需随代码提交。
不提交：上传文献、生成 PDF/图片、请求审计与模型缓存、`output/`、`tmp/`、构建产物、配置密钥和 `__pycache__`。
`start-server.ps1` 含本机环境默认路径，作为本地启动辅助脚本单独保留，不纳入此表格功能 PR。

提交前用 `git status` 核对文件范围，并用 `git diff --cached --stat` 和 `git diff --cached` 检查实际暂存内容；普通 `git diff` 不包含已暂存内容或未跟踪文件。避免把整个工作区无差别加入提交。
环境隔离测试修正只补齐不同平台的进程 mock，保持原有环境变量断言，建议保留。代码复查的小修正和历史检查结论见 [table-code-review.md](table-code-review.md)。本文不记录实时 Git 操作状态。
