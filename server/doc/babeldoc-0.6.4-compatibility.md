# BabelDOC 0.6.4 表格兼容性核对

日期：2026-11-02。代码基于原项目 v4.1.8（`5dd2eaf`）与本地表格功能合并后的工作树。pdf2zh-next 固定为 2.9.0。本次不修改 DeepSeek 行为。

## 基线整理

恢复 `server.py`、`utils/config.py`、`utils/execute.py` 的表格接线：健康检查能力字段、请求解析、运行时校验、配置中的原生表格开关覆盖、CLI 私有参数和子进程适配器启动。此前这些接线已在本地未提交修改中移除，插件仍会发送表格模式，造成服务端功能与测试不一致。保留已有排版修改。

使用仓库的 `server/zotero-pdf2zh-next-venv/Scripts/python.exe`，而不是缺少 pydantic 的 Conda `pdf` 环境。原环境为 BabelDOC 0.6.2 / pdf2zh-next 2.9.0 / PyMuPDF 1.25.2。0.6.4 wheel 仅安装到 `tmp/babeldoc-064`，在独立测试进程中优先导入，未替换原有环境。

两个 BabelDOC 版本的 Server 测试均为 139 项：138 通过，1 项可选 Flask/CLI 集成测试跳过。插件 16 项测试及 TypeScript `--noEmit` 检查通过。版本白名单只增加 0.6.4，不放开未经验证的版本；真实 IL 排版测试在两个版本均执行。

## 上游优化是否重复

对比实际安装的 0.6.2 与 0.6.4 Python 源码：

- `paragraph_finder.py` 和 `il_translator_llm_only.py` 内容相同。
- `typesetting.py` 的变动为换行时增加 `font_size * scale * line_skip` 下限，修复混合 Latin/CJK 字形包围盒偏矮造成的行距压缩。
- IL 字体结构新增带默认值的 Type3 字体元数据；其他变化包括 Type3 指标、解析器、安全修复和布局检测像素预算。

0.6.4 的通用行距修复不能替代本方案的表格语义分组、标签保护、数值保留、受限单元格排版及恢复原文。两者会在底层 `_layout_typesetting_units` 相遇，因此仍需要输出对比，不能仅凭方法签名不变断言兼容。

上游说明：[BabelDOC 0.6.4](https://github.com/funstory-ai/BabelDOC/releases/tag/v0.6.4)。完整本地文件差异清单及排版 diff 保存在 `output/pdf/babeldoc-compatibility/`。

## 三组 PDF 对比的方法

输入为此前用户提供的同一份 23 页、35 个检测表格的测试包，SHA-256：`437891f11bd4e89cc134077bf1241456d51cd516dc37d02d84efefba64d6ea26`。

1. BabelDOC 0.6.2 + 当前增强方案。
2. BabelDOC 0.6.4 原生表格路径（RapidOCR）。
3. BabelDOC 0.6.4 + 当前增强方案。

执行真实 PDF 解析、布局检测和排版输出，复用历史模型响应，不调用在线翻译 API。增强方案按完整分析提示词匹配结构分析响应；翻译按页码和完整输入文字映射历史译文，并重新绑定当前批次 ID。这是在测试程序中控制变量，不改变生产缓存或生产翻译逻辑。

原生路径与增强路径的段落拆分不同，各自复用对应历史响应，因此跨方案比较不能当作“相同译文下”的严格优劣实验。原生路径包含正文翻译，增强路径保持正文源字形；只比较表格裁图，不对整页正文差异作功能结论。历史响应缺失时明确保留原文，并在 JSON 中逐项记录。

本地审阅入口为 `output/pdf/babeldoc-compatibility/review.html`，包括源表格与上述三组结果；`summary.json` 记录版本、响应缺失和两个增强版本的布局差异。输入论文和生成图片不纳入源码提交。

## 本次结果

- 三组均完成 23 页 PDF 输出。两个增强版本各分析 35 张表格、生成 509 个布局单元；最终回放均无请求错误，在线 API 请求数为 0。
- 两个增强版本的 509 个布局单元全部匹配，最终文字、字号缩放及逐字形位置/字体/字号差异均为 0。本测试包没有触发可观察到的版本升级排版变化，不代表混排行距修复对所有 PDF 均无影响。
- 增强回放有 9 次输入（7 个不同的页码/文字组合）没有对应历史译文并保留源文字：第 1 页重复出现的 `(Seen)`、`(Unseen)`，第 17 页的 `Background`、`restoration`、`inpainting`、`Rendering`、`compositing`。原生回放另有 1 个段落缺少历史译文。它们属于回放覆盖限制，不作为漏译率或模型质量指标。
- 已查看全部 35 张表格的六张汇总渲染图，并放大核对第 5 页长描述表格。两个增强版本视觉一致；第 5 页的按完整语义单元排版与原生路径仍有明显区别，原生结果仍出现短片段分行、列内留白不均等现象。第 6 页、多级表头及图片混合表也保留两种处理路径的差异。未作逐字语义审校或全部页面的溢出自动证明。

因此目前没有理由因 0.6.4 的通用行距修复删除本方案。0.6.4 已加入增强适配白名单；白名单外版本在导入私有引擎 API 前跳过适配，在日志提示检测到的版本及降级原因，并为本次 CLI 执行启用 `--translate-table-text`，不修改保存的用户偏好。此策略也适用于 API 的 `preserve` 模式：降级后遵循原生行为，不再保证保留原表格字形。后续版本的增强适配仍须独立验证，降级也不保证上游引擎自身兼容所有 PDF。

降级行为另有回归测试覆盖：未知版本即使移除私有模块也不会导入它们；CLI 会启用原生表格参数、跳过 worker 包装；受支持版本继续安装并恢复增强策略。实现后 Server 全量为 143 项，142 通过、1 项可选集成测试跳过。

## 支持范围

本次验证只覆盖 BabelDOC 0.6.2、0.6.4 与 pdf2zh-next 2.9.0。它不证明尚未发布的 pdf2zh-next 或 BabelDOC 版本兼容，也不覆盖任意 Type3 PDF、超大扫描页、独立 exe、OCR workaround 或完整合并单元格重建。可选 Flask/CLI 集成测试仍需单独启用；本次不是新的在线模型质量评测。
